\begin{abstract}
Retrieval-augmented generation (RAG) improves a language model's output by conditioning it on passages retrieved from an external corpus, but most of this work assumes a single, roughly homogeneous document collection. Practical knowledgebases violate that assumption: websites, PDFs, video transcripts, and code repositories are extracted, chunked, cited, and queried in different ways, and one query may need to draw on several at once. This survey organizes the techniques required for grounded question answering over such heterogeneous, multi-source knowledgebases: dense retrieval and RAG foundations, hybrid lexical-dense reranking, chunking strategies for long and structured documents, modality-specific retrieval for web, video, and code, multi-document fusion, and confidence estimation with abstention. Rather than treating each technique in isolation, we examine how each is affected once a corpus is assembled from structurally different sources at query time. One system, SAGE, which ingests and answers questions over crawled websites, PDFs, video transcripts, and GitHub repositories through a shared pipeline, appears as a brief case study showing how the surveyed ideas instantiate in a working implementation. We close with open problems in cross-modal fusion, confidence calibration, incremental re-indexing, and evaluation that remain unresolved across the literature.
\end{abstract}

\section{Introduction}

Retrieval-augmented generation (RAG) has become the dominant pattern for grounding language-model output in an external corpus: a retriever selects passages relevant to a question, and a generator conditions its answer on those passages rather than on parametric memory alone \cite{lewis2020rag}. Since its introduction, RAG research has expanded rapidly along several axes, including retriever architecture, passage fusion, iterative retrieval, and calibration, nearly all of it measured on a single, relatively uniform corpus such as a Wikipedia dump, a set of internal wiki pages, or a collection of PDF manuals. That uniformity is analytically convenient: it fixes one chunking strategy, one citation format, and one notion of a document.

That convenience disappears once the material a user wants to query spans structurally unrelated sources — web pages, formatted documents, spoken-language transcripts, and source code — each with its own extraction process, natural retrieval unit, and citation semantics. Answering one query against whichever source holds the relevant evidence, with a citation identifying both the source and the location within it, requires composing techniques largely designed and evaluated one modality at a time. This composition problem, rather than any single retrieval or generation advance, is what motivates a survey dedicated to heterogeneous knowledgebases.

The survey is organized around that composition. Section~\ref{sec:foundations} reviews retrieval and generation foundations common to every RAG system. Section~\ref{sec:reranking} turns to reranking and hybrid lexical-dense retrieval, whose role grows once a candidate pool is drawn from sources with different lexical characteristics. Section~\ref{sec:chunking} examines chunking, where the right retrieval unit for a code file, a video transcript, and a prose document rarely coincides. Section~\ref{sec:modality} surveys the modality-specific retrieval literatures for web, video/transcript, code, and multi-document fusion. Section~\ref{sec:confidence} addresses confidence estimation and abstention, which gain an added dimension when a system must judge not only \emph{what} to retrieve but whether it retrieved \emph{enough} to answer responsibly. Section~\ref{sec:casestudy} draws on one system, SAGE, to show how these pieces combine in a working pipeline. Section~\ref{sec:challenges} collects recurring open problems, and Section~\ref{sec:conclusion} concludes.

\textbf{Scope and relation to prior surveys.} General RAG design is already surveyed at length \cite{gao2023ragsurvey}, and hallucination in generation has its own dedicated survey \cite{ji2023hallucination}; we duplicate neither. Instead of surveying RAG technique by technique over an assumed-uniform corpus, we organize technique choices around the points of strain that emerge once a corpus is assembled from structurally different sources at query time, which is why chunking, reranking, and confidence calibration are reconsidered in Sections~\ref{sec:reranking}--\ref{sec:confidence}. The literature below was selected by starting from the four modality-specific retrieval areas of Section~\ref{sec:modality} and working back to the shared machinery each assumes, rather than from any single venue's proceedings; we claim no exhaustive coverage of any one area on its own terms.

\section{Problem Definition and Terminology}
\label{sec:problem}

Before surveying techniques, it is worth stating precisely what changes when a RAG system moves from one corpus to several heterogeneous ones, since much of the terminology in the RAG literature implicitly assumes a single corpus and does not distinguish these concerns.

We use \emph{source} to mean one ingested unit with its own identity and extraction process (one crawled website, one PDF, one video, or one code repository), and \emph{knowledgebase} to mean a set of sources a user has grouped together. A \emph{chunk} is the unit actually embedded and retrieved, produced from a source by some modality-specific chunking function. A \emph{query} may target one source, an entire knowledgebase, or an explicit, user-selected subset of sources spanning one or more knowledgebases; we call the last case a \emph{combined-source query}, and it is the case that introduces requirements a single-corpus system does not have.

Three properties distinguish multi-source retrieval from ordinary multi-document retrieval within one corpus:

\begin{itemize}
\item \textbf{Heterogeneous extraction.} Each source type has its own extraction pipeline (Section~\ref{sec:modality}) that yields text of different lexical character (crawled prose, PDF-extracted prose with layout artifacts, ASR-transcribed speech, and source code) before any retrieval model sees it.
\item \textbf{Heterogeneous chunking.} As Section~\ref{sec:chunking} discusses, the natural retrieval unit differs by modality (a paragraph, a timestamped transcript segment, a function-scoped code block), so a single global chunking function is a simplification rather than a given.
\item \textbf{Source-level accountability.} A citation in a multi-source system must identify which source, not just which passage, produced a piece of evidence. A combined-source query also carries an implicit expectation that every source the user explicitly selected was actually considered, a requirement with no analogue when the corpus is one undifferentiated collection.
\end{itemize}

These three properties recur through the rest of the survey: Sections~\ref{sec:foundations} and~\ref{sec:reranking} cover the shared retrieval foundation and the source-level accountability that reranking must provide; Section~\ref{sec:chunking} covers heterogeneous chunking directly; Section~\ref{sec:modality} covers heterogeneous extraction per modality; and Section~\ref{sec:confidence} returns to source-level accountability from the confidence side.

\section{Dense Retrieval and RAG Foundations}
\label{sec:foundations}

The move from sparse lexical matching to learned dense representations began with semantic-matching architectures such as DSSM \cite{huang2013dssm} and matured into dual-encoder retrievers, of which Dense Passage Retrieval (DPR) \cite{karpukhin2020dpr} is the canonical instance: queries and passages are embedded separately and compared by inner product or cosine similarity. Because the passage side is fixed at index time, its embeddings can be precomputed offline and served through approximate nearest-neighbor search, leaving query-time cost independent of corpus size — the property that makes a single shared index across modalities feasible at all, since web, PDF, transcript, and code chunks can be encoded by the same model and placed in one searchable space. That design also carries an assumption worth flagging early: that one encoder's geometry is equally suitable for prose, speech, and code. Sections~\ref{sec:reranking} and \ref{sec:challenges} return to the consequences of that assumption.

Retrieval-augmented generation \cite{lewis2020rag} pairs such a retriever with a generator that conditions its output on the retrieved passages, marginalizing over retrieved evidence rather than depending on parametric memory alone. Fusion-in-Decoder \cite{izacard2021fid} refined the coupling by having a sequence-to-sequence model encode each retrieved passage separately, so the decoder attends across all of them at once, scaling better with passage count than concatenating them into a single encoder pass. The design space around this core, what to retrieve, when, how many passages, how to fuse them, and whether to iterate, is already surveyed at length \cite{gao2023ragsurvey}. Its relevance here is specific: once a system ingests more than one kind of source, every one of those choices must be resolved per modality rather than once globally, and that requirement is this survey's throughline.

Every dense retriever rests on a sentence- or passage-embedding model. Sentence-BERT \cite{reimers2019sbert} made dense retrieval practical by producing embeddings whose cosine geometry is directly usable for ranking and clustering, sidestepping the quadratic cost of scoring every query-passage pair with a full cross-encoder. Distillation pushes the same idea toward deployment: MiniLM \cite{wang2020minilm,wang2020minilmv2} transfers a large teacher's attention behavior into a compact student, trading a little accuracy for markedly lower latency and memory use, a balance decisive for interactive retrieval rather than offline batch indexing. The distilled checkpoint \texttt{all-MiniLM-L6-v2} \cite{minilm_modelcard} has become a common default in open-source RAG tooling. In a multi-source setting, committing to one such encoder is also a decision to represent every modality with weights trained on a single kind of text, an issue taken up in Section~\ref{sec:challenges}.

Two design choices here take on added weight once a system indexes several source types together. One is the approximate nearest-neighbor index: its distance metric is usually treated as an implementation detail orthogonal to retrieval quality, yet fixing it once for an entire shared index presumes a sentence encoder's embedding geometry behaves comparably across prose, transcribed speech, or code — a presumption rarely tested directly. The other concerns training data: DPR's original recipe \cite{karpukhin2020dpr} draws negatives from a single corpus's question-passage pairs, so a system reusing an off-the-shelf encoder inherits a negative distribution unlikely to match the mixed prose/transcript/code negatives it meets at query time. Fine-tuning one encoder against a deliberately multi-modal negative distribution appears absent from the literature, an open problem revisited in Section~\ref{sec:challenges}.

\section{Reranking and Hybrid Retrieval}
\label{sec:reranking}

Dense retrieval alone systematically underperforms on queries dominated by exact terms, identifiers, proper nouns, error codes, which a bi-encoder's semantic similarity underweights. Two broad families address this. One re-scores an initial dense-retrieved list with a more expensive, jointly-encoded model: cross-encoder rerankers \cite{nogueira2019bert} score a query and passage together, and late-interaction models such as ColBERT \cite{khattab2020colbert} compute token-level similarity, keeping much of a cross-encoder's accuracy at lower cost. The other family blends dense and lexical signals directly. CLEAR \cite{gao2020clear} trains a dense retriever to capture the residual a classical scorer such as BM25 \cite{robertson2009bm25} misses; Reciprocal Rank Fusion \cite{cormack2009rrf} merges independently produced ranked lists by rank position alone, with no need for calibrated, comparable scores. Concretely, RRF scores a document $d$ as
\[
\mathrm{RRF}(d) = \sum_{i} \frac{1}{k + \mathrm{rank}_i(d)},
\]
summed over each ranked list $i$ in which $d$ appears, with $\mathrm{rank}_i(d)$ its position in list $i$ and $k$ a small constant (commonly 60) damping the influence of any single list's very top ranks; a document absent from a list simply contributes zero rather than requiring an imputed score. This rank-only property is what makes RRF attractive for fusing across sources with different lexical and semantic characteristics (Section~\ref{sec:modality}): it needs no assumption that a 0.73 semantic score from a prose retriever means the same thing as a 0.73 score from a code retriever, only that each retriever's own ranking is locally meaningful.

This blending family suits multi-source retrieval for reasons a single-corpus system never confronts. Its candidate pool is drawn from structurally different sources at once, mixing prose, code fragments, and transcript segments whose embeddings and lexical statistics come from extraction and chunking processes with dissimilar characteristics (Section~\ref{sec:chunking}), and a rank-based or explicitly weighted fusion tolerates that dissimilarity better than a score premised on one uniform passage distribution. A structural consequence follows too: the output must decide not only \emph{which} passages are best but \emph{whether at least one passage from each requested source} reaches the final answer, so ranking becomes a two-stage problem, scoring followed by selection under a source-coverage constraint, rather than scoring and truncating alone.

The cost asymmetry between these two families determines which one a system can afford. A cross-encoder or ColBERT-style pass \cite{nogueira2019bert,khattab2020colbert} runs a neural forward pass per candidate — easy to justify over the top 100 candidates once per query, but proportionally more expensive precisely when a multi-source system widens its pool to guarantee per-source representation. A closed-form hybrid score behaves differently: computed from quantities retrieval already produced, so widening the pool for fairness leaves its cost unchanged. This tradeoff is understated in studies that measure cost only against a single-corpus, unwidened baseline.

\section{Chunking Strategies}
\label{sec:chunking}

Retrieval granularity is usually decided before any retrieval model is chosen: documents are split into fixed-size, overlapping chunks, and the chunk, not the document, becomes the unit that is embedded, indexed, and retrieved. Fixed-size chunking with a modest overlap remains the dominant practical choice because it is cheap, deterministic, and works passably across many document types, though its tradeoffs have increasingly been studied directly rather than assumed. Chunk-size sensitivity varies by domain and document structure, as shown for financial reports, where headers, tables, and dense terminology interact with the chosen chunk boundary in ways that measurably affect downstream retrieval quality \cite{jimenoyepes2024chunking}. ``Late chunking'' \cite{gunther2024latechunking} inverts the usual order of operations: it encodes a long document with a long-context embedding model first and derives chunk-level embeddings from token-level representations afterward, so each chunk's embedding still reflects surrounding context that a naively-chunked-then-embedded passage would lose. Comparative studies \cite{merola2025chunking} suggest no single strategy dominates across document types, precisely the situation a multi-source system is in by construction: a website's prose, a PDF's mixed prose-and-table layout, a video transcript's spoken, punctuation-light stream, and a source code file's line-oriented structure differ enough that a strategy tuned for one is unlikely to suit another. In practice, multi-source systems tend to adopt a shared default chunker for prose-like sources and a distinct unit for whichever modality least resembles prose (most often code, by line, or transcript, by time/character band), rather than forcing one chunking function onto every modality.

Chunk overlap deserves separate comment from chunk size, since the two are often conflated as one hyperparameter. Overlap exists to prevent a fact straddling a chunk boundary from being unrecoverable by either resulting chunk; its cost is redundant storage and embedding computation proportional to the overlap fraction, a fixed, easily-budgeted cost, unlike chunk size, whose effect on retrieval quality is corpus- and query-dependent and harder to budget for in advance. A further wrinkle specific to multi-source systems is that overlap's benefit is not uniform across modalities: a transcript chunked by a time/character band, where segment boundaries already align with natural pauses in speech, needs overlap less than dense, boundary-agnostic prose extracted from a PDF's continuous text flow. That suggests, though we know of no study measuring it directly, that a single global overlap parameter, like a single global chunk size, is a simplification a genuinely multi-modal chunking strategy would eventually need to relax.

An alternative to fixed-size chunking is to place boundaries adaptively, at points where adjacent sentences' embeddings diverge beyond some threshold (``semantic chunking''), so a boundary tends to coincide with an actual topic shift rather than an arbitrary character count. Late chunking \cite{gunther2024latechunking} is one instance of this adaptive-boundary family, and comparative evaluations \cite{merola2025chunking} generally find adaptive strategies competitive with, but not uniformly better than, well-tuned fixed-size chunking, at the cost of an extra embedding pass over candidate boundaries. For a multi-source system this cost tradeoff is itself modality-dependent: computing sentence-level embeddings for adaptive boundaries is a small additional cost for prose, where sentence segmentation is already solved, but is far less well-defined for source code, where a ``sentence'' has no clear analogue and syntax-aware boundaries (function or class scope) are already a more natural criterion than embedding divergence.

A different response to the same problem is to stop treating chunk granularity as a single choice at all. RAPTOR \cite{sarthi2024raptor} recursively clusters and summarizes chunks into a tree, so retrieval can draw on a fine-grained leaf chunk, a paragraph-level summary, or a whole-document summary depending on the abstraction level a query needs — a broad question answered from a high node, a specific one from a leaf, without forcing a single chunk size to serve both. The motivation resembles the source-overview chunk examined in Section~\ref{sec:casestudy}, though the mechanism differs: both add a synthetic higher-level representation because broad queries are otherwise poorly served by fine-grained chunking, but RAPTOR builds a full multi-level tree through recursive LLM summarization, a heavier device than a single deterministic overview chunk derived from source statistics without any generative summarization.

\section{Modality-Specific Retrieval Challenges}
\label{sec:modality}

\subsection{Web Documents}
Retrieval over crawled web content inherits two problems documents-at-rest avoid. Content must be extracted from a live, often JavaScript-rendered page rather than a static file, and the crawl frontier must be bounded by domain, depth, or page count to avoid indexing unbounded linked content. Both sit upstream of retrieval yet directly determine what becomes retrievable: a page that fails to render, or falls outside the crawl's limits, is simply absent from the corpus, a silent failure mode a static-document corpus never exhibits. Near-duplicate content is a subtler hazard: templated navigation and boilerplate repeated across a site's pages can dominate a naive chunk's lexical signature, so without explicit stripping a retriever may return several near-identical, low-information chunks in place of one genuinely relevant one.

\subsection{Video and Transcript QA}
Two features set transcript-based video QA apart. The retrieval unit is inherently temporal: a useful citation names a timestamp range rather than a document title, and benchmarks such as TVQA \cite{lei2018tvqa} enforce this by scoring temporally localized evidence rather than whole-video labels. The text is also less clean when it comes from an automatic transcript rather than a human-authored one, carrying transcription errors, missing punctuation, and imprecise sentence boundaries that other sources' text usually avoids, bearing directly on how far a system should trust a confidence score computed uniformly across all its sources (Section~\ref{sec:confidence}). Frameworks such as LLoVi \cite{zhang2024llovi} handle long-form video QA by converting video to language (captions or transcripts) and reasoning over that text with a long-context model, the same reduction to retrievable text plus timestamps that a transcript-based multi-source system relies on. Chunk size interacts awkwardly with the timestamp-labeling requirement: a short transcript chunk yields a precise citation timestamp but a weak, fragmentary retrieval signal, since spoken language lacks the self-contained sentence structure of written prose, while a longer chunk strengthens the signal at the cost of a timestamp that only loosely locates the answer within a multi-minute span.

\subsection{Code-Repository Retrieval}
Code differs from prose in ways that shape both extraction and retrieval. A repository is a directory tree of files linked by import and dependency relationships, and a chunk boundary aligned to function or class scope serves retrieval better than an arbitrary character cut, motivating line- or syntax-aware chunking over prose's character-budget chunking. Semantic code search was an early target for dense methods, exemplified by CodeSearchNet \cite{husain2019codesearchnet}, and has since grown into retrieval-augmented code completion that must decide not just what to retrieve but \emph{where in the repository} to look. RepoCoder \cite{zhang2023repocoder} interleaves retrieval and generation so an initial, imperfect generation drives better subsequent retrieval, while Repoformer \cite{wu2024repoformer} learns when repository-level retrieval is worth its cost. A repository's own scaffolding, README, directory layout, and conventions, is itself retrievable signal distinct from any single file's contents. One point receives only partial treatment in the literature: an import or call-graph edge between two files is direct evidence of relatedness that text-similarity retrieval cannot perceive, so a chunk-level retriever blind to the dependency graph discards structure a compiler already has.

\subsection{Multi-Document and Multi-Source Fusion}
Retrieving well from any single source is necessary but not sufficient once a query may be legitimately answered by evidence spread across several sources at once. End-to-end training of a reader and retriever jointly over multiple documents \cite{sachan2021multidoc} treats multi-document evidence aggregation as a first-class training objective rather than an artifact of independently ranking single documents and concatenating the top results. Reciprocal Rank Fusion \cite{cormack2009rrf}, discussed above as a reranking technique, is equally a multi-source fusion technique when its inputs are ranked lists retrieved independently \emph{per source}. A distinguishing requirement of multi-source (as opposed to merely multi-document) retrieval is source-level fairness: a user who explicitly selects several sources jointly expects each to be actually considered, which pure top-$k$-by-score selection does not guarantee if one source's evidence is systematically weaker or sparser than another's. This requirement is orthogonal to whichever fusion technique is used: unweighted rank fusion, learned re-weighting, or a joint reader-retriever objective can all be layered with an explicit source-coverage constraint applied after scoring, since the constraint operates on \emph{which source produced each candidate}, provenance metadata fusion techniques generally carry through but rarely act on themselves.

\section{Confidence, Calibration, and Abstention}
\label{sec:confidence}

A grounded QA system that always answers, regardless of retrieval quality, will eventually answer confidently from irrelevant or insufficient evidence. Selective prediction under distribution shift \cite{kamath2020selective} frames this as a decision the system should make explicitly, answer or abstain, rather than an emergent property of whatever the generator happens to produce. Whether a language model's own reported confidence can be trusted for this is itself contested: \cite{kadavath2022knowwhattheyknow} finds larger models can be reasonably well calibrated on some self-assessment tasks, but hallucination surveys \cite{ji2023hallucination} document broad and persistent failure modes where fluent, confident-sounding generation is simply wrong — arguing for grounding the abstention decision in retrieval evidence rather than the generator's self-report wherever that evidence is available. Retrieval augmentation has itself been shown to reduce hallucination directly in open-ended generation \cite{shuster2021retrieval}, further supporting gating on retrieval quality specifically rather than only on downstream generation behavior after the fact.

Two recent systems fold the abstention decision into the model's own reasoning rather than an external gate. Self-RAG \cite{asai2024selfrag} trains a single model to emit reflection tokens that decide at generation time whether to retrieve and whether its own output is supported by what was retrieved, rather than computing that decision upstream from a fixed formula. Corrective RAG \cite{yan2024crag} takes a middle path, adding a lightweight retrieval evaluator that labels evidence as correct, incorrect, or ambiguous and triggers a distinct action per label (using the evidence, discarding it for a web search, or blending the two) — closer to the confidence-gate pattern described here, with a learned classifier in place of a closed-form heuristic. Neither system has been evaluated on a deliberately multi-source, multi-modal corpus of the kind this survey concerns, though both point toward moving calibration into a learned component, which a multi-source system could in principle apply per source type rather than uniformly.

Multi-source retrieval complicates calibration in a way single-corpus systems never encounter: when sources have systematically different retrieval-quality distributions, the noisier text of an automatic video transcript against the cleaner text of a crawled webpage, say, a single fixed threshold applied uniformly will be miscalibrated for at least one of them. A system must either normalize confidence per source type before thresholding, or make an explicit, stated exception where uniform thresholding is known to misfire.

In practice abstention is not binary: a system can refuse outright, answer with an attached caveat, or ask a clarifying follow-up. The caveat option weakens the guarantee from ``no unsupported claims reach the user'' to ``flagged but still delivered,'' which can be the more defensible choice for noisy transcripts, where a strict refusal threshold would decline a disproportionate share of genuinely answerable questions. Which response to select for a given confidence band remains underspecified in the surveyed literature: most selective-prediction work \cite{kamath2020selective} treats abstention as binary, leaving the graded per-source-type policy to individual builders' judgment rather than any established methodology.

\section{Case Study: SAGE}
\label{sec:casestudy}

SAGE (Semantic Analysis and Generation Engine) ingests four source types, crawled multi-page websites, PDFs, YouTube video transcripts, and GitHub repositories, through modality-specific extractors terminating in a common chunk representation. It embeds all chunks with the same sentence encoder \cite{reimers2019sbert,wang2020minilm} and answers questions against one, several, or all of a user's sources through a single retrieval, reranking, confidence-gating, and generation pipeline. We do not repeat SAGE's full architecture here; instead we use two design decisions as concrete instances of ideas introduced earlier, mapped onto Section~\ref{sec:modality}'s challenges: a bounded, boilerplate-diluted web crawl, a timestamp/signal tradeoff and noisier ASR text for video, structure beyond individual files for code, and source-level fairness under score-only ranking for combined queries.

\textbf{Overview chunks as a chunking-strategy instance.} Section~\ref{sec:chunking} noted that no single chunking strategy dominates across the modalities a multi-source system ingests, and that broad, non-specific queries pose a particular retrieval problem: a question like ``what is this about'' has poor lexical and semantic overlap with any single content chunk, because the answer lives in a source's overall structure rather than any one passage. SAGE addresses this without tuning the chunk size at all. It adds a synthetic, deterministic \emph{overview chunk} to every source at ingestion time, built from the source's own statistics and excerpts (crawled page titles, transcript timestamps, or, for a GitHub repository, a live-introspected on-disk directory tree and detected project conventions), with no additional generative model call. In the terms of Section~\ref{sec:chunking} this is a chunking-strategy decision rather than a generation-time summarization feature: it is an extra chunk added to every source purely to change what is retrievable, and it needs no labeled training data or model fine-tuning to extend to a new modality.

\textbf{The diversity floor as a multi-source-fusion instance.} Section~\ref{sec:modality} identified source-level fairness as a requirement specific to multi-source (not merely multi-document) retrieval: a query naming several sources should not silently omit one because its single best-matching chunk scored lower than another source's several good chunks. SAGE addresses this with a diversity floor: before a fixed number of citation slots is filled by reranked score, each explicitly combined source has its single best-scoring chunk reserved, and only the remaining slots are filled by score across all sources — a direct instance of the score-then-select-under-a-coverage-constraint pattern anticipated in Sections~\ref{sec:reranking} and \ref{sec:modality}. A live run confirmed the behavior beyond unit tests: a query spanning a website and a topically unrelated code repository still cited both, and a three-source query cited each source rather than dropping the weakest-scoring one. The relevance here is that source-level fairness failures look benign when a reranker is examined alone and surface only under genuinely combined, multi-source queries.

\textbf{Confidence gating with a stated per-modality exception.} Consistent with Section~\ref{sec:confidence}, SAGE computes a single retrieval-derived confidence score from its top-ranked and top-three blended scores plus a small evidence-count bonus, refusing to answer in grounded mode below a fixed threshold. Video is the one exception: its chunks are exempted from hard refusal and instead receive a lower-confidence warning, since automatically transcribed text is measurably noisier than the system's other sources. This realizes the per-source exception anticipated in Section~\ref{sec:confidence}, applied to one modality rather than a general calibration procedure.

\textbf{Evidence, not a benchmark.} SAGE's test suite (95 tests across 12 files, covering chunking, URL normalization, reranker and confidence sanity checks, per-modality overview generation, and an end-to-end API suite) shows the mechanisms above are implemented and exercised, not a quantitative retrieval- or answer-quality result. SAGE reports no benchmark score against a labeled dataset, and none is constructed here, since a combined-modality benchmark able to support one does not yet exist (Section~\ref{sec:challenges}).

At the product level, SAGE sits between two familiar categories: consumer ``chat with your sources'' tools such as NotebookLM \cite{notebooklm2023}, and composability frameworks such as LangChain \cite{langchain} and LlamaIndex \cite{llamaindex}, matching neither, being an opinionated pipeline rather than a finished application or a general library. \section{Open Challenges}
\label{sec:challenges}

Several problems recur across the surveyed systems and papers without a settled answer.

\emph{Cross-modal fusion at the scoring level} remains largely heuristic. Blended semantic-lexical scores, rank fusion, and learned combination methods (Section~\ref{sec:reranking}) each rest on different, usually untested assumptions about whether a score from one modality's chunk is comparable in magnitude to a score from another's. SAGE's diversity floor avoids the question by guaranteeing representation instead of asserting cross-modality score comparability, yielding a fairness guarantee at the expense of a true relevance ordering across sources.

\emph{Confidence calibration across heterogeneous corpora} is equally unsettled. Per-source-type exceptions, such as the video-transcript exception in Section~\ref{sec:casestudy}, are practical patches rather than calibrated solutions; no published method jointly calibrates one retrieval-confidence score across genuinely heterogeneous modalities using a single labeled dataset.

\emph{Incremental re-indexing} has received little attention in the multi-source case. Chunking strategies (Section~\ref{sec:chunking}) are typically presented as one-time operations, yet a source that changes over time, a recrawled website or an updated repository, forces a decision about which chunks to preserve and which to re-embed. Content-addressed chunk identifiers make that tradeoff explicit but do not resolve it.

\emph{Evaluation} for multi-source, multi-modal RAG trails single-corpus evaluation. Most retrieval and QA benchmarks, including several in Section~\ref{sec:modality}, are modality-specific, and no widely adopted benchmark jointly measures retrieval quality, citation correctness, and confidence calibration across web, document, video, and code sources combined in one query — the kind of benchmark that would let systems like SAGE be compared on equal terms rather than by architecture description alone. Standard metrics widen the gap rather than close it: Recall@$k$, MRR, and nDCG are each defined against a single fixed relevance judgment, presuming a labeled query-document pair from one corpus. Extending them to a combined-source query first requires deciding whether relevance judgments are pooled across sources or required per source, the latter capturing the fairness property of Sections~\ref{sec:modality} and \ref{sec:casestudy}, and no standard convention yet governs that choice.

\emph{Fine-tuning against a multi-modal negative distribution}, raised in Section~\ref{sec:foundations}, is a training-side gap: nearly every widely used open-source sentence encoder, including the one in our case study, was trained on question-passage pairs from a single kind of corpus, and published work fine-tuning one encoder against hard negatives spanning prose, transcript, and code together appears to be missing; the common alternative is separate per-modality encoders reconciled afterward.

\emph{Dependency-aware retrieval for structured sources}, raised in Section~\ref{sec:modality}'s discussion of code, generalizes beyond code: a website's link graph and a PDF's cross-references are structural signals most chunk-level dense retrievers discard just as they discard a repository's import graph. GraphRAG \cite{edge2024graphrag} takes structure this seriously within a single corpus, extracting an entity-relationship graph via LLM and pre-summarizing its communities so broad questions can be answered without any single retrieved chunk; extending that across genuinely different modalities, linking a code symbol to the PDF paragraph documenting it, for instance, remains open.

\section{Conclusion}
\label{sec:conclusion}

Grounded question answering over heterogeneous, multi-source knowledgebases relies on the same core techniques as single-corpus RAG: dense retrieval, hybrid reranking, chunking, and confidence-gated generation. Each must be reconsidered once the corpus is assembled from structurally different sources at query time. Chunking must accommodate prose, transcripts, and code without assuming one size fits all; reranking must pair with an explicit source-fairness mechanism as soon as queries can name several sources at once; confidence estimation must either normalize across source-type-specific quality distributions or state its exceptions explicitly. SAGE's overview-chunk mechanism and diversity floor served as checkable instances of the latter two adjustments, illustrating how one system resolves tradeoffs the broader literature leaves open.

Four problems stand out as most in need of dedicated attention as multi-source RAG systems mature: cross-modal score comparability, joint confidence calibration, incremental re-indexing, and combined-modality evaluation. The highest-leverage next steps follow directly: a standardized multi-modal benchmark should score retrieval quality, citation correctness, and confidence calibration across web, document, video, and code sources together rather than one at a time; retrieval confidence should be calibrated jointly across heterogeneous corpora instead of patched per source type; and retrieval/reranking pipelines should choose their chunking and fusion strategy adaptively by source modality rather than applying one global configuration to every ingested source.
